# Design handoff

The design canvas holds four artboards. The hosted canvas is the viewing copy; this folder is
the record.

| File | Artboard | Size | Implemented in |
|---|---|---|---|
| `Main.dc.html` | Editor workspace | 1440 x 900 | `site/app/` |
| `Site.dc.html` | Project site | 1280 x 1400 | `site/index.html` |
| `Desktop.dc.html` | Desktop app | 1280 x 800 | `desktop/app/` |
| `Wizard.dc.html` | Server setup wizard | 760 x 560 | `desktop/wizard/` |
| `Editor2.dc.html` | Editor, Material Design 3, geographic layout | 1440 x 900 | `site/app/` (1.2.0) |

## Desktop app

A native window around the real editor. The File menu is open on Open recent, because native
file handling is what the desktop app adds over the web page. The map fills the window.

Deviations, both deliberate: the save dialog is the operating system's own, so it is not drawn;
and a recent-maps sidebar from the first draft was dropped in favour of File > Open recent,
which is where the shipped app puts it.

## Server setup wizard

Five steps in a rail, shown on the last step: the network address as the one large value, Open
in browser and Copy address, four checks, a Stop the server action and Back / Finish. The
language selector and version sit at the foot of the rail, as in the shipped wizard.

## Review

A design guideline pass (Stageshow 1.1.1, commit `299140f`) was applied, followed by an
independent review of rendered frames. It found ten items; nine were fixed and re-filmed:

1. Desktop: dialog hid a line end. Fixed by removing the drawn dialog.
2. Desktop: map bunched with an unnamed station. Fixed: map spans the window, every station named.
3. Desktop: sidebar 60% empty. Fixed: sidebar removed.
4. Wizard: void under the checks. Fixed: network reachability check, hint and Stop action.
5. Wizard: dead space under the step rail. Fixed: language selector and version.
6. Desktop: dialog without a scrim. Fixed by removing the drawn dialog.
7. No issue (real words throughout).
8. Wizard: two check styles. Fixed: one filled check style.
9. Desktop: offline pill cramped. Fixed by removing the pill (the app shows offline status in Help > About).
10. Menu label contrast. Not changed: Edit and View use the same ink as File; the reviewer marked it unverified.

Frames: `frames/*-v1.png` before, `frames/*-v2.png` after. They are rendered offline by
`tools/render-dc.mjs`, which expands each artboard's template and values, then captured with a
headless browser at 1x. They are design frames, not screenshots of the shipped app.

Not applicable to real application screens: the guideline kit's React parts, animation,
cursor choreography, compact phone width and marketing crop layouts.

## Editor, geographic layout (1.2.0)

Generated by `tools/gen-editor2.cjs` from the real station coordinates and VIVA stops, so routes
sit where the editor draws them over OpenStreetMap tiles (zoom 11). Material Design 3: top app bar
with a layout segmented button, navigation rail, search bar, list items with stop counts and
frequency chips, a docked inspector side sheet with filled fields, a switch, FABs and a snackbar.

An independent review of the first frame found nine items. Fixed and re-filmed: the floating
inspector card that hid the map is now a docked side sheet; every route row shows its service
type and stop count; the select field has a dropdown arrow; the snackbar has an action; badges
show peak and off-peak and are anchored on their routes; the map is reframed so Toronto, York
Region and every label are clear of the side sheet. Not changed: 11px attribution text (required
attribution, kept small by convention). Frames: `frames/editor2-v1.png` to `editor2-v3.png`.

The shipped editor was checked against this artboard in headless Edge (see the project HANDOFF).

## Releases 1.3 to 1.6

Artboards `Editor13`, `Import14`, `Journey14`, `Print15` and `Plan16` show the screens planned
for 1.3 (command palette, service patterns, facilities, timeline), 1.4 (GTFS import, trip planner
and travel times), 1.5 (auto-schematic, styles, print layout) and 1.6 (scenarios and compare,
simulation, coverage, share link, GTFS export). The coverage numbers in `Plan16` are placeholders
for the layout, not results. Each is generated by a script in `tools/`.

Two independent reviews were run. Fixed and re-filmed: dialogs and the command palette are centred
on the window with a scrim over the whole window; inspector gaps filled (branches); chips at one
height; selected segments and filter chips carry a check mark; the trip-planner fields no longer
stretch; the simulation bar no longer clips. Left for implementation, where real Material
components are used: floating-label fields, slider value labels, radio affordance in the scenario
list, and larger preset thumbnails. Frames: `frames/*-v1.png` before, `*-v2.png` after.

## Times16

`Times16.dc.html` (generated by `design/tools/gen-times16.cjs`) shows the zoomed-in map with estimated and set travel-time pills and the pill popover, the inspector Travel times list (steppers with the estimate as supporting text) and the Vehicles cards (drag handle, edit and delete buttons). Implemented in `site/app/mod-times.js` and `mod-vehicles.js`.

## Tweaks on every board

Every board declares the same two Tweaks, with the same names and defaults, in its `data-props`:

| Tweak | Editor | Default | What it does |
| --- | --- | --- | --- |
| `accent` | colour (`#185BBB`, `#0B6E4F`, `#9461A8`, `#16181D`) | `#185BBB` | Colour of buttons, selection, checkboxes and links. On the home page board it sets `--primary`. |
| `motion` | switch | on | Off stills every animation and transition on the board. |

Boards: Main, Site, Desktop, Wizard, Editor2, Editor13, Import14, Journey14, Print15, Plan16,
Deploy16, Deploy16b, Flash16, Instances16, Home16, Gtfs16, Times16. The defaults reproduce the
reviewed frames (checked pixel for pixel on Deploy16b and Instances16 with fonts loaded). Main,
Site, Desktop and Wizard previously had an `accent` lever defaulting to `#1F5FBF`; it now uses
the shared default `#185BBB`.

The board generators in `design/tools/gen-*.cjs` write boards without Tweaks. After running one,
run `node design/tools/add-tweaks.cjs design/<Board>.dc.html` to add them again.
